# Delivering a lecture for read aloud

Load this when the person studies by listening, with the app's read-aloud button, while a map and
notes for the lesson are already built ([lesson-build.md](lesson-build.md)). It covers one lecture:
one part of a lesson. *(kstack: the operator's rule)*

## Send the lecture as a reply of its own

Read aloud plays a whole reply and can't play a selection. So a lecture reply holds nothing but the
lecture. Status, links, admin and questions go in other replies. When a reply calls a tool after
its text, the app groups the text with the tool calls, so no tool call follows the lecture. The
reply ends, and the read-aloud button appears. In every reply that isn't a lecture, write the answer
first and do any tool work after it, so the learner can read while the work runs. *(kstack: the
operator's rule)*

## Prepare before you write

- **Cue the video.** Show the Browser pane first. Then open the video at this part's moment,
  paused, as [video-capture.md](video-capture.md) describes.
- **Check that the map already holds this part.** If the learner's questions showed that a part
  needs more, add it to the notes and the map before this lecture.

*(kstack: the operator's rule)*

## Open by saying where to look

Start with the part's box on the map and the video's tab and timestamp, said in words: "The video is in
the other tab, paused at three minutes six seconds." The learner drives the map. Move the map only
when the learner asks. *(kstack: the operator's rule)*

## Teach the part the notes already hold

The lecture follows that part's notes and map branch, in the same order. Each paragraph starts by
naming the map box it covers by what the box says, such as "The next box says heat breaks a few
bonds." Never tell the learner to open a box: some boxes have nothing under them, and the learner
opens branches when the learner wants. So what the learner hears matches what the learner reads. One lecture covers one part. When checking sources for the notes
turned up a fact an earlier lecture got wrong, open with a short spoken correction. *(kstack: the
operator's rule)*

## Write it to be heard

- Load the teach skill before the first lecture of a session, and write every sentence to it.
- Use plain paragraphs. No bullets, tables, symbols, abbreviations or links, because a voice reads
  them badly.
- Write the way a good science documentary narrates: short, concrete and plain. Three short
  paragraphs make a full lecture.
- Run the unslop and technical-writing passes before sending.

*(kstack: the operator's rule)*

## Leave the questions to the learner

End without a check question. The learner asks about what didn't land, and says when to go on.
*(kstack: the operator's rule)*
