# elon

Musk's five-step algorithm, run as written. The order carries the whole value — the classic
and expensive error is simplifying or automating a part that should have been deleted.

1. **Make the requirements less dumb.** Question every requirement, and attach a name to
   each — a person, not a department. Requirements from smart people are the most dangerous,
   because nobody questions them.
2. **Delete the part or the process step.** Not "could this be smaller" — does it need to
   exist at all. This is the step that carries the value: people default to adding and
   overlook subtraction unless something cues them to consider it, and this is the cue.

   **Delete until just right, not further.** Musk's rule is to over-delete and add back
   at least 10%, because in a factory adding a part back costs a part. Here a cut from working
   code is a lost capability someone approves (build's check 2), and an approved loss stands
   rather than being reversed, so the trade inverts.
3. **Simplify or optimize.** Only now, and only what survived step 2.
4. **Accelerate cycle time.** A manufacturing step. Skipped for design work.
5. **Automate.** Last. Automating an unstable design freezes it.

## Confirm against the artifact

Run the five steps first, then **read the thing you just judged and enumerate its parts from
the text** — not from what you remember of it. Anything you didn't name during the pass gets
named now.

A pass run from memory is strongest on whatever was written most recently, which is the
opposite of what this algorithm is for. (Not Musk's — a safeguard for running it.)

## Output

Report the pass as: **what each requirement's owner turned out to be**, **what was deleted
and why**, and **what was added back**. A pass that deletes nothing is possible but rare —
when it happens, name the parts you tried to cut and what kept them, so the reader can see
the pass ran.
